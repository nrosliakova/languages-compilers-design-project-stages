--- Part 1: the loop feature ------------------------------------------------

Already in the repository, and kept as it was:

  - WhileNode, and the checker's visit_while, AstPrinter.visit_while and
    CodeGenerator.visit_while, which emits the condition, body and end blocks
    and the back edge.

    checker, and the error format.

Written by the agent and reviewed by me:

  - ForNode and BreakNode in the AST.
  - parse_while, parse_for and parse_break, and the contextual dispatch in
    parse_statement. The dispatch is the part that matters: `while` starts a
    loop only when the next token is not "=", "." or "(" or ";", `for` starts a
    loop only when a type name follows, and `break` is a statement only as
    `break;`. That is why an existing test that declares a variable named
    `while` still compiles.
  - The checker's loop depth, the counter's own scope, and the rule that the
    counter is declared with the locked padlock.
  - CodeGenerator.visit_for, which emits five blocks and leaves the loop before
    the increment when the counter reaches the last value, and visit_break,
    which branches to the end block of the innermost loop kept on a stack.
  - Nine test programs, the grammar productions, and the README section.

Why the counter is locked: the loop leaves before adding one when the counter
equals the last value, so the single addition in the loop can never overflow,
which is only true while nothing else can change the counter.

--- Part 2: the optimizer ---------------------------------------------------

Reused from my own practice 9, and changed for this repository:

  - The idea of one visitor that counts, for every declaration, the reads that
    resolve to it, and for every function, the calls that name it, then a
    second pass that rebuilds statement lists without the dead ones, repeated
    until a round removes nothing.
  - The rule that a declaration whose initialiser contains a call is never
    dropped, and that parameters, fields and member functions are never
    removed.

Rewritten rather than copied, because the ASTs differ:

  - UseCounter and Pruner here follow the checker's resolved links (VarNode.decl,
    FieldAccessNode.decl, CallNode.fn) over this repository's nodes, which
    include ForNode, CallStmtNode and extra_inits, and they walk the tree with
    a helper that does not follow those links, so a recursive function cannot
    send the walk into itself.
  - The call counting in the practices version counts calls to methods through
    their lowered structs; here member functions are never removed, so a call
    from a method body counts and nothing else is needed.

Written from scratch:

  - The inlining pass, the --optimize flag, and its place in the driver that
    repeats the three passes until nothing changes.
  - The inlining moves the body instead of copying it, so the declaration links
    the checker already resolved stay valid and the compiler does not have to
    re-check the tree. Each parameter becomes a local declaration holding the
    argument, the final bye becomes a result declaration, and every parameter
    and local of the body gets a #N suffix so it cannot collide with the
    caller's names.
  - One bug I found by running the suite with --optimize: the first version
    looked for the statement holding the call from the outside in, so a call
    inside a member function was hoisted to the top of the program and the code
    generator crashed on a field reference. The search now takes the innermost
    block first, and tests/stage2/ok/global_function_in_method.txt passes with
    and without the flag.

## Task 2 — the optimizer (4 pt)

`--optimize` works in any position, and `--optimize --ast` prints the tree after the passes. The three transformations repeat until a round changes nothing.

- **Unused variables.** One visitor counts reads through the links the checker already resolved, so two declarations sharing a name are two counters — shadowing costs nothing. Assignments to a dead declaration go with it; a declaration whose initialiser calls is kept, because the call may print or read.
- **Unused functions.** Uncalled global functions are removed with their bodies, repeatedly: `opt_functions_chain.txt` needs three rounds. Member functions are never removed, and a call from a method counts.
- **Inlining.** A function called once has its body moved into the caller: parameters become locals holding the arguments, the final `bye` becomes a `result#N` declaration standing where the call stood, and every local gets a `#N` suffix. It **moves** rather than copies, so the checker's links stay valid and the tree isn't re-checked. Left alone, and documented: recursive functions, functions called twice, bodies that leave through a `bye` inside a `chat`, calls in a loop header, and member functions.

The one bug the suite caught: my first `locate` searched from the outside in, so a call inside a member function was hoisted to the top of the program and codegen crashed on a field reference. It now takes the innermost block first; `global_function_in_method.txt` passes both ways.
